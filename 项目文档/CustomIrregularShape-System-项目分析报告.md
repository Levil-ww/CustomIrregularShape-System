## 1. 一句话概括

一个**独立运行的 Python / PyQt5 桌面应用**，把矩形花型素材图按"目标文件名"自动匹配后，**无缝排版并裁剪成圆桌 / 弧形台（异形）轮廓**，保留原素材的花纹层次、边框和图案，导出为成品 JPG / PNG；支持上传草图并用**本地 Windows OCR** 识别尺寸。它明确定位为 SmartShapeCrop 的**独立重写版本**，运行时不依赖 SmartShapeCrop。

## 4. 功能总览

### 4.1 核心流程（文件名驱动）

```
输入目标名称（如 花幔;80X140cm）
  → 解析尺寸/花型/材质
  → 在素材图库中匹配「同材质、同花型」的矩形 JPG
  → 统一等比缩放 + 中心等距裁剪
  → 裁剪到圆形 / 弧形台轮廓
  → 保留原花纹层次与边框 → 导出 JPG / PNG
```

- **尺寸补偿**：长边、短边各 +1cm（**总尺寸补偿**，非每边 +1cm），仅在工作流中补偿一次，导出不再补偿。
- **匹配规则**：横竖统一按"长边 × 短边"比较；先限定同材质、同花型，再按**比例差**排序，比例相同再按尺寸差。仅候选矩形 JPG/JPEG；文件名含"裁剪有图 / 圆形 / 直径 / 水池 / 挖角"的素材被排除。无同花型素材时**明确报告失败，不自动替换**其他花型。
- **输出命名**：保持输入的目标名称，只按格式改扩展名，不追加实际尺寸。

### 4.2 两种轮廓

- **圆桌（circular）**：轮廓为圆与横向条带的交集 `x²+y² ≤ (D/2)²` 且 `|y| ≤ H/2`；`H=D` 时为完整圆；上下直边长 `√(D²−H²)`。
- **弧形台（arc）**：上下**对称短圆弧**模型，额外输入上下直边长度。鼓出 `s=(W−L)/2`，半径 `R=((H/2)²+s²)/(2s)`，左右各自独立圆心。直边**不参与尺寸补偿**。
- **同心内圆**：目前为**填充圆**（复用外素材边框与花纹缩放），非真实镂空。
- 几何全部支持**等距内缩**（offset），内缩后半径减 t、半高减 t，再重算直边交点，保证边框层次沿轮廓平行。

### 4.3 草图识别

- 上传 PNG/JPG/BMP/TIFF 草图 → **本地 Windows OCR**（**不上传图片、不下载模型**）。
- 红色标注优先分离识别，再识别原图；结合标注位置关联"最大宽度 / 总高 / 直边"，并处理被 OCR 分开的数字与小数点。
- 识别结果**始终需人工核对**，缺失数据留给手工输入；改尺寸后需重新核对；换目标名会清除上一单草图与直边。
- 手工输入兜底；首版**不支持**任意曲线、非对称轮廓、自动描边拟合。

### 4.4 素材排版（自动模式，项目技术含量最高的部分）

自动读取"最外缘到中央花纹的完整边框带"，按**视觉结构**分类处理（**明确禁止按花型名称加特例**）：

| 分类 | 处理策略 |
|---|---|
| 满铺素材 | 以 `max(目标宽/原图宽, 目标高/原图高)` 统一等比缩放，保持原图中心等距裁剪；**禁止镜像/重复/拉伸** |
| 独立留白图案类 | 按纯色背景与连通图案自动识别图案组与真实矩形框线，整体等比缩放，保留原最小留白 |
| 装饰背景独立画框类 | 识别封闭矩形 + 内部花纹 + 四侧背景周期，中央花纹与双细线框整体等比适配 |
| 浅色中央框类 | 识别浅色封闭内框，框线随轮廓适配，内部英文独立等比取样 |
| 英文环 / 句子条带 | 沿周长连续映射，**下半圈文字旋转 180° 而非镜像**；稀疏英文按满幅装饰带处理，局部短句保留原对角位置 |
| 周期装饰边框 | 排除原矩形转角后提取**整数个完整周期**闭合新周长，消除起止相位跳变；加宽只扩展纯色留白，装饰不拉伸 |

关键工程细节：
- 各层厚度按统一比例换算成厘米，再沿截圆等距轮廓重排；装饰按原物理比例沿周长映射。
- 大图在**最长边 2400px** 的识别尺度定位边界，再回**原分辨率**附近定位分隔线；花纹与边框仍从原图采样。
- 不使用生成式重绘、不修改素材色彩、不叠加首版固定描边；无法可靠识别时**明确降级提示并保留原图填充**，可转手工工具。

## 5. 架构与分层

**严格单向依赖：**

```
GUI / CLI  →  workers  →  services  →  core  →  models
```

| 层 | 目录 | 职责 | 约束 |
|---|---|---|---|
| models | `shape_crop/models/` | frozen dataclass、厘米参数、业务校验 | 不依赖 Qt / 文件操作 |
| core | `shape_crop/core/` | 几何、采样、渲染、映射（纯计算） | 不依赖 GUI / Worker / 文件路径 |
| services | `shape_crop/services/` | 文件名解析、图库匹配、工作流、OCR、导出 | 组织核心能力 + 文件操作 |
| workers | `shape_crop/workers/` | QThread 后台线程、进度/取消信号 | 仅依赖 models + services |
| gui | `shape_crop/gui/` | 编辑参数、选文件、呈现结果 | **不实现裁剪数学** |

**数据流：**
```
ProductRequest → workflow.resolve_request → DesignSpec（不可变快照，厘米）
  → RenderWorker/SketchWorker → design_service.generate
      → materials.prepare → source_renderer.render_source / renderer.render
          → geometry.create_shape（CircularBand / ArcBand）→ sampling
      → export.save_image
```

**关键设计约束：**
- 所有尺寸在模型中用厘米；像素转换仅发生在渲染/输出计算时。
- `height_cm ≤ diameter_cm`；内圆必须完整位于外内容轮廓内。
- 参数是 `frozen dataclass`，后台任务拿快照；运行期禁用参数编辑；关窗前先请求取消，等线程结束再关闭。

## 6. 性能工程（亮点）

项目对性能投入很深，且有实测数据支撑（`docs/PERFORMANCE.md`）：

- **图库索引**：针对用户真实场景（**221,905 张、持续增长的 SMB 共享图库**），桌面版用单个 `ReadDirectoryChangesW` 递归监听（64KiB 缓冲，兼容 SMB），按文件事件**增量更新内存索引**，正常换单**不再遍历网络目录**。
  - 实测：第二种花型匹配从 **17.42s → 0.011s**（目录核对模式 vs 监听索引模式）。
- **内存缓存**：素材读取与边框分析缓存最多 **8 项 / 256MiB**；只读数组防污染；按文件标识/大小/纳秒时间戳失效。
- **大图解码**：预览先用 JPEG draft 按比例缩小解码，分析/渲染最长边 2400px，显示预览 1200px；导出独立读取原分辨率，不用缩图缓存。
- **采样优化**：`float32` 插值减少临时内存；全尺寸放大时复用相同源行的横向插值结果。
  - 实测（弧形台 151×91cm、150 DPI，约 4792 万像素）：渲染 **25.25s → 18.80s**（约 −26%）；渲染 + JPG 保存 **26.07s → 19.54s**（约 −25%）。
- **分块渲染**：`block_rows` 分块，块间响应取消；最终画布仍驻留内存，上限 **1.8 亿像素**。
- **编码**：PNG 用 `compress_level=1` 快速无损压缩（像素/透明度不变，文件可能稍大）；JPG 质量 95。
- **进度语义**：渲染 0–90 → 编码保存 94 → 成功 100，未完成编码**不会替换**已有目标文件。

## 10. 局限与待办（据 README / ARCHITECTURE）

- 未接入 PSD 导出、色彩配置（ICC）转换、持久化图库索引（索引仅在进程内）。
- 同心内圆为**填充圆**，非真实镂空；不支持多个/偏心内圆。
- 非周期图案接缝优化、任意曲线、非对称轮廓、自动描边拟合尚未实现。
- 依赖 Windows 系统 OCR（需有可用 OCR 语言，优先英语、回退用户语言），非跨平台。
- 仓库**无 LICENSE**，商用/二次分发前需与作者确认授权。

## 11. 适用场景与总评

**适用场景**：电商/家居布料类商家（如桌布、圆桌布、花幔）——给定客户定制尺寸与花型素材，批量生成异形裁剪成品图。

**总评**：
- 这是一个**完成度高、工程规范强、性能优化扎实**的垂直领域桌面工具。
- 亮点在于把"矩形花型 → 异形轮廓"的**边框连续映射**问题处理得非常细致（周期闭合、相位防跳变、文字不镜像、留白不拉伸）。
- 代码组织清晰（严格分层、frozen 模型、纯计算 core），文档与测试完善，可维护性好。
- 主要限制是**平台绑定 Windows（OCR）**、**无开源许可证**、以及部分高级几何/格式能力仍在路线图中。
