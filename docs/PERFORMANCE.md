# 性能优化验证

使用同一工作区 `.venv\Scripts\python.exe benchmarks/performance.py` 在修改前后测量。
测试为临时图库 6000 个 JPG 文件名、30 个花型；素材为固定随机种子的 1600×900 RGB PNG，
成品参数为 140×78cm、40 DPI（2205×1228px）。重复匹配取 12 次平均，素材准备和编码取 3 次平均。

| 阶段 | 修改前 | 修改后 | 对比 |
|---|---:|---:|---:|
| 首次匹配 | 20.2ms | 71.9ms | 首次解析所有花型并建立索引，有额外成本 |
| 重复匹配 | 23.2ms | 3.8ms | 约 6.1 倍速度 |
| 重复素材准备 | 146.9ms | 0.1ms | 复用读取和边框分析结果 |
| 生成成品画布（素材已使用过） | 1122ms | 426.7ms | 约 2.6 倍速度 |
| PNG 编码保存 | 361.3ms | 161.7ms | 约 2.2 倍速度 |
| JPG 编码保存 | 51.3ms | 35.8ms | 编码质量保持不变，绝对差异较小 |

这些是本地合成基准，不代表所有真实素材的固定速度；PNG 压缩收益与图像内容有关。
首次扫描、素材首次读取、大幅高 DPI 画布仍有成本。索引和素材缓存仅在程序运行期间保留。
PNG 采用较低压缩级别，像素和透明度保持无损，但文件可能更大。
插值改为 float32，随机采样与旧实现比较的通道差不超过 1 个灰度级。

匹配优化复用花型解析及分组，仍核对目录条目。不能只靠目录时间戳：测试发现 NTFS
会延迟反映快速删除；已验证连续新增、删除、改名以及新增子目录都能刷新匹配结果。
素材缓存按文件标识、修改时间、大小及参数失效，限制为 8 项 / 256MiB，只读数组防止污染。

验证命令：`python -m pytest tests -q --tb=short`，结果 **84 passed**。
覆盖后台预览到 JPG 导出、PNG 像素/DPI、旧输出原子保护、进度完成时机、
图库变更、素材替换、采样精度，以及现有几何、边框、花纹保真与布局回归。

界面检查：`python benchmarks/gui_preview.py` 生成 `outputs/gui-preview.png`、
`outputs/gui-empty.png`、`outputs/gui-compact.png`，检查 1280×850 与 1000×720 的布局。
